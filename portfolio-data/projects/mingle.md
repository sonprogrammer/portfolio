# Mingle

## 프로젝트 개요

- 기간: 2023.11 ~ 2023.11
- 유형: 5인 팀 프로젝트
- 역할: 프론트엔드 개발
- 설명: 음악을 중심으로 사용자와 플레이리스트를 연결하는 플레이리스트 공유 SNS 서비스입니다.

## 담당 기능

### 유저 관리

회원 정보 관리와 팔로우 관계를 기반으로 사용자 간 연결 기능을 구현했습니다.

- 유저 소개 및 회원정보 수정 기능
- 회원정보 수정 과정의 이메일 중복 확인 기능
- 팔로잉 관계를 기반으로 한 사용자 추천 기능
- 팔로우한 사용자 목록 조회 및 화면 연동

### 음악 인터랙션

사용자가 등록한 음악 데이터를 조회하고 좋아요 상태 변경을 UI에 반영했습니다.

- 사용자가 등록한 곡 삭제 기능
- 곡 좋아요 토글 및 변경 상태 UI 반영
- 최신순으로 정렬된 곡 목록 조회

### 플레이리스트 추천

날씨와 사용자의 음악 취향을 활용해 상황에 맞는 플레이리스트를 조회하도록 구현했습니다.

- 플레이리스트와 작성자 정보 연결 및 화면 표시
- OpenWeather API의 날씨 데이터를 활용한 플레이리스트 조회
- 사용자 음악 취향을 기반으로 한 플레이리스트 조회

## 서비스 아키텍처와 데이터 흐름

서버 데이터 캐싱과 API 요청 구조를 중심으로 프론트엔드 데이터 흐름을 구성했습니다.

### TanStack Query 기반 서버 데이터 관리

조회 빈도가 높은 서버 데이터를 TanStack Query로 관리하고 캐싱해 불필요한 네트워크 요청을 줄였습니다.

- 플레이리스트 등 조회 데이터를 서버 상태로 관리
- TanStack Query 캐시를 통해 반복 요청 최소화
- 데이터 변경 이후 필요한 상태를 UI에 동기화

### Recoil 기반 클라이언트 상태 관리

서버에서 조회하는 데이터와 프론트엔드 내부에서 사용하는 상태를 구분해 관리했습니다.

- Recoil을 이용한 클라이언트 상태 관리
- TanStack Query 서버 상태와 클라이언트 상태의 역할 분리
- 상태 변경 결과를 사용자 화면에 반영

### API 성격에 따른 Axios 요청 분리

내부 API와 외부 API의 인증 요구사항이 다른 점을 고려해 Axios 요청 구조를 분리했습니다.

- 내부 API 요청에 Authorization 인증 헤더 적용
- 외부 API 요청에는 인증 헤더가 포함되지 않도록 분리
- API 성격에 따라 요청 책임을 명확하게 구성

### OpenWeather API 기반 외부 데이터 연동

외부 날씨 데이터를 서비스의 플레이리스트 데이터와 연결해 날씨에 따른 음악 큐레이션 기능을 구현했습니다.

- OpenWeather API를 통한 날씨 데이터 조회
- 날씨 데이터를 플레이리스트 조회 조건에 활용
- 외부 API와 서비스 API 요청 흐름 분리

## 트러블슈팅: OpenWeather API CORS 오류

### 문제

공통 Axios 인스턴스를 사용해 OpenWeather API를 호출했을 때 CORS 오류가 발생해 날씨별 플레이리스트 데이터를 불러오지 못했습니다.

### 원인

내부 API 인증을 위해 설정한 Axios 인터셉터가 외부 API 요청에도 적용되면서 Authorization 헤더가 OpenWeather 요청에 함께 포함되고 있었습니다.

### 해결

네트워크 요청 헤더를 확인해 Authorization 헤더 충돌을 파악했습니다. 인증이 필요하지 않은 외부 API 요청은 별도의 Axios 인스턴스로 분리했습니다.

### 결과

- OpenWeather API의 CORS 및 Preflight 문제 해결
- 날씨별 플레이리스트 데이터 정상 수신
- 내부 API와 외부 API의 요청 책임 분리
