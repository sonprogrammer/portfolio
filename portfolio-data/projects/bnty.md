# BNTY

## 프로젝트 개요

- 기간: 2024.09 ~ 2024.10
- 유형: 개인 프로젝트
- 설명: 트레이너와 회원을 연결해 QR 출석, PT 관리, 실시간 소통을 지원하는 PT 관리 서비스입니다.

## 프로젝트를 시작한 이유

트레이너로 근무하며 PT 횟수를 수기로 관리하는 과정에서 회원과 트레이너 모두 잔여 횟수를 명확하게 확인하기 어렵고 개인정보 및 수기 관리가 불편하다는 점을 경험했습니다. 이러한 관리 과정을 개선하기 위해 프로젝트를 시작했습니다.

## 포트폴리오 기능 체험 환경

- 트레이너와 회원 역할을 전환하며 주요 기능과 데이터 흐름을 체험할 수 있습니다.
- 별도의 회원가입 없이 HttpOnly Cookie에 저장한 세션 식별자를 기반으로 데모 사용자를 구분합니다.
- 이 체험용 인증 방식은 실제 프로젝트의 인증 방식과 다릅니다.
- 1:1 채팅은 무료 실시간 서버의 월 사용량 한도에 따라 일시적으로 제한될 수 있습니다.

## 서비스 아키텍처와 데이터 흐름

사용자 흐름부터 REST API, 실시간 통신, 데이터 저장까지 전체 서비스 구조를 설계했습니다.

### 트레이너와 회원 역할 기반 서비스 흐름

- 트레이너와 회원의 역할별 기능 및 화면 분리
- 트레이너와 회원 간 1:1 연결 관계 관리
- 연결된 회원을 기준으로 PT, 운동 기록, 채팅 데이터 관리
- 동일한 브라우저에서 역할을 전환하며 전체 서비스 흐름을 체험하도록 구성

### QR 기반 출석 및 PT 관리 흐름

오프라인 PT 수업에서 발생하는 출석과 잔여 수강 횟수 관리를 QR 기반 데이터 흐름으로 자동화했습니다.

- 트레이너 QR을 회원이 스캔해 출석 처리
- 출석 처리와 동시에 잔여 PT 횟수 차감
- 변경된 PT 정보를 트레이너와 회원 화면에 반영

### React와 Node.js 기반 Client/Server 구조

사용자 인터페이스와 비즈니스 로직을 분리하고 REST API를 통해 클라이언트와 서버가 데이터를 주고받도록 구성했습니다.

- React와 TypeScript 기반 클라이언트 구현
- Node.js와 Express 기반 REST API 서버 구축
- 사용자, PT, 운동 기록, 채팅, 앨범 데이터 API 분리

### 서비스 데이터 및 상태 관리

MongoDB로 트레이너·회원 관계, PT 횟수, 운동 기록, 채팅 내역을 관리했습니다. TanStack Query와 Recoil을 활용해 서버 데이터 캐싱과 클라이언트 상태의 책임을 분리했습니다.

- Mongoose Schema를 이용한 서비스 데이터 구조 정의
- TanStack Query 기반 Custom Hook으로 데이터 조회·변경 로직 분리 및 캐싱 관리
- Recoil을 활용한 사용자 역할 및 클라이언트 상태 관리
- 트레이너·회원 관계를 기준으로 PT, 운동 기록, 채팅 데이터 연결

### REST와 Socket.IO 실시간 통신

저장된 데이터 조회와 실시간 이벤트의 책임을 분리했습니다. 즉시성이 필요한 채팅은 Socket.IO로, 일반적인 조회와 저장은 REST API로 처리했습니다.

- REST API를 통한 기존 채팅 내역 조회
- Socket.IO Room 기반 1:1 메시지 실시간 전달
- 메시지 전송과 읽음 상태 이벤트 분리

## 기술 선택 배경

엘리스 부트캠프 수료 직후 시작한 프로젝트로, 학습한 기술을 실제 서비스에 적용하며 숙련하는 것을 우선했습니다.

- React, TypeScript, Recoil, Express, MongoDB는 부트캠프에서 학습한 스택을 실제 프로젝트에 적용하기 위해 선택했습니다.
- 서버의 일지 기록 등은 TanStack Query로 관리했습니다.
- 여러 컴포넌트에서 반복되는 상태와 비즈니스 로직은 Custom Hook으로 분리해 데이터 처리와 UI 표현의 책임을 구분했습니다.
- 1:1 채팅에는 이벤트와 Room 단위 연결 관리가 필요했습니다. 기본 WebSocket보다 채팅방 관리와 재연결 처리를 간단하게 구현할 수 있어 Socket.IO를 선택했습니다.
- 트레이너와 회원이 모바일에서 반복 사용하는 서비스 특성을 고려해 앱과 유사한 사용 경험을 제공하려고 PWA를 적용했습니다.

## 트러블슈팅: 한글 IME 입력 시 메시지 중복 전송

### 문제

한글의 마지막 글자가 조합 중인 상태에서 Enter를 누르면 동일한 메시지가 두 번 전송됐습니다.

### 원인

한글 입력은 IME 조합 과정을 거치므로 Enter 입력 시 조합 완료 이벤트와 키보드 이벤트가 함께 발생할 수 있었습니다.

### 해결

KeyboardEvent의 `nativeEvent.isComposing` 값을 검사해 한글 조합이 완료된 경우에만 메시지를 전송하도록 분기했습니다.

### 결과

- 한글 입력 환경에서 동일 메시지 중복 전송 방지
- Enter를 이용한 기존 전송 방식 유지

## 트러블슈팅: 초기 렌더링 성능 저하

### 문제

초기 페이지 진입 시 여러 컴포넌트와 데이터 요청이 동시에 처리되면서 LCP가 약 8초까지 증가했습니다.

### 원인

초기 화면에서 필요하지 않은 컴포넌트까지 한 번에 로드됐고, 서로 독립적인 API 요청도 순차적으로 처리되고 있었습니다.

### 해결

React.lazy와 Suspense로 초기 번들을 분리하고 독립적인 요청을 Promise.all로 병렬 처리했습니다. 반복 렌더링이 발생하는 컴포넌트에는 메모이제이션을 적용했습니다.

### 결과

- Lighthouse 5회 측정 기준 LCP 8.0초에서 1.1초로 약 86% 개선
- 네트워크 대기 시간 및 불필요한 렌더링 감소
